### CSS Module vs 일반 CSS 비교
1. **CSS Module의 장점:**
    - 클래스명 충돌 방지 (자동으로 고유한 이름 생성)
    - 컴포넌트 스코프 스타일링 (스타일이 특정 컴포넌트에만 적용)
    - 타입스크립트와의 더 나은 통합
    - 실수로 다른 컴포넌트의 스타일을 덮어쓰는 것 방지

2. **일반 CSS의 장점:**
    - 더 간단한 사용법
    - 기존 CSS 작성 방식과 동일
    - 전역 스타일 적용이 쉬움
    - 클래스 이름을 직관적으로 확인 가능

3. **CSS Module의 단점:**
    - 약간 더 복잡한 문법 (`styles.className` 형식으로 사용)
    - 전역 스타일 적용이 추가 작업 필요
    - 동적 클래스명 사용이 조금 더 복잡함

4. **일반 CSS의 단점:**
    - 클래스명 충돌 가능성
    - 큰 프로젝트에서 유지보수가 어려울 수 있음
    - 의도치 않은 스타일 상속 문제 발생 가능

### 사용 권장 상황
**CSS Module 사용 권장:**
- 큰 규모의 프로젝트
- 여러 개발자가 협업하는 경우
- 재사용 가능한 컴포넌트 개발
- 스타일 격리가 중요한 경우

**일반 CSS 사용 권장:**
- 작은 규모의 프로젝트
- 빠른 프로토타입 개발
- 전역 스타일이 많이 필요한 경우
- 기존 CSS 코드를 재사용하는 경우

===>
선택은 프로젝트의 규모와 요구사항에 따라 달라질 수 있습니다. 작은 프로젝트이고 전역 스타일을 많이 사용한다면 일반 CSS를, 큰 프로젝트에서 스타일 충돌 방지가 중요하다면 CSS Module을 사용하는 것이 좋습니다.

최종 결과는 같지만, 원본 데이터를 직접 변형하지 않음으로써 몇 가지 이점을 얻을 수 있다.

불변성을 사용하면 복잡한 기능을 훨씬 쉽게 구현할 수 있다. 
특정 작업을 실행 취소하고 다시 실행하는 기능은 이 게임에만 국한된 것이 아닌 앱의 일반적인 요구사항이다. 
직접적인 데이터 변경을 피하면 이전 버전의 데이터를 그대로 유지하여 나중에 재사용(또는 초기화)할 수 있다.

불변성을 사용하는 것의 또 다른 장점이 있다. 
기본적으로 부모 컴포넌트의 State가 변경되면 모든 자식 컴포넌트가 자동으로 다시 렌더링 됩니다. 여기에는 변경 사항이 없는 자식 컴포넌트도 포함됩니다. 리렌더링 자체가 사용자에게 보이는 것은 아니지만 성능상의 이유로 트리의 영향을 받지 않는 부분의 리렌더링을 피하는 것이 좋습니다. 불변성을 사용하면 컴포넌트가 데이터의 변경 여부를 저렴한 비용으로 판단할 수 있습니다.
